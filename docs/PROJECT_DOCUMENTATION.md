# Zscaler AI Security Intelligence Center
## Technical Project Documentation

**Type:** Interactive URL security analysis application  
**Language:** Python | **UI:** Streamlit | **Database:** SQLite  
**Threat intelligence:** Google Safe Browsing API | **PDF:** ReportLab | **Tests:** Pytest

## 1. Overview

The Zscaler AI Security Intelligence Center is a modular Streamlit application that examines URLs and presents security findings. It combines (1) structural URL analysis using deterministic parsing and rule-based indicators and (2) a Google Safe Browsing lookup for known threat matches. It also provides scan history, security analytics, and PDF reporting.

This version is rule-based. It does not train or deploy a machine-learning model and makes no ML accuracy, precision, recall, or performance claims.

## 2. Objectives

- Parse URLs and extract structural characteristics without visiting destination websites.
- Produce an explainable structural risk score using application rules.
- Query Google Safe Browsing for known threat matches.
- Store scan records in SQLite.
- Present findings through Streamlit pages and visualizations.
- Export scan data and generate PDF reports.
- Test core parsing, validation, and risk-engine behavior with Pytest.

## 3. User workflow

1. The user submits a URL in the Streamlit URL Scanner.
2. Input validation checks the value and supported scheme.
3. The URL analyzer parses the URL and extracts structural attributes.
4. Feature/risk components evaluate those attributes.
5. The application requests a Google Safe Browsing lookup.
6. The application combines the structural assessment and API result into an overall verdict.
7. The scan is saved to SQLite and displayed in the UI.
8. The user can review scan history and generate a security report.

## 6. Technology stack

- **Python:** application logic, parsing, API requests, database operations, and reporting.
- **Streamlit:** interactive web UI.
- **Python standard library:** `urllib.parse`, `ipaddress`, and `re` for URL parsing and inspection.
- **SQLite:** local scan-history persistence.

- **Pandas and visualization libraries:** data handling and visualization where used by the application.

Exact installed package versions are defined in `requirements.txt`.

## 7. Risk assessment and verdict

The application presents a structural score separately from its overall verdict. The score is generated by deterministic application rules and is not a probability that a URL is malicious.

A confirmed Google Safe Browsing match can elevate the overall verdict to CRITICAL even if the structural score is low. A previously executed test returned a structural score of 5/100, structural classification LOW, Google status MATCH, threat category `SOCIAL_ENGINEERING`, and overall verdict CRITICAL. This is an observed test example, not a universal expected result.

## 8. Data storage

SQLite stores scan history. `database/db.py` and `database/scan_history.py` manage database setup and scan persistence. The schema was extended to store Google Safe Browsing status, threat matches, and overall verdict. The local database file is runtime data and should generally not be committed to a public source repository.

## 9. API key configuration

The Google Safe Browsing API key is configured locally in `.streamlit/secrets.toml`:

```toml
GOOGLE_SAFE_BROWSING_API_KEY = "YOUR_API_KEY"
```

Do not commit this file, embed the key in source code, or include it in screenshots. Ensure `.gitignore` excludes it.

## 10. Installation and execution

```bash
git clone https://github.com/kruthika243/ZSCALER_AI_SECURITY_CENTER.git
cd ZSCALER_AI_SECURITY_CENTER
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Create `.streamlit/secrets.toml` locally, configure the API key, and run:

```bash
streamlit run app.py
```

Run tests:

```bash
python -m pytest tests/ -v
```

## 11. Limitations

- The structural score is rule-based, not a calibrated probability.
- A low score does not prove a URL is safe.
- Google Safe Browsing `NO_MATCH` does not guarantee safety; newly created or unlisted threats may not match.
- `ERROR` means the lookup could not be completed and must not be interpreted as `NO_MATCH`.
- Structural analysis does not visit the destination or inspect page content, redirects, scripts, hosting infrastructure, or runtime behavior.
- Results depend on implemented rules and external API availability/configuration.
- SQLite is used for this local project and is not, by itself, a distributed production database.
- No trained ML model or ML benchmark is included in this version.

## 12. Responsible use

Use the application as an educational analysis aid, not as the sole basis for deciding whether to visit a URL. Do not browse known phishing test URLs. Keep API credentials private. Treat API errors and missing matches as inconclusive.

## 13. Future enhancements

Potential work includes broader integration tests, more robust URL edge-case handling, improved API error observability, database indexing, authentication and authorization, deployment hardening, and a separately evaluated ML component if justified by an appropriate dataset and evaluation plan.
